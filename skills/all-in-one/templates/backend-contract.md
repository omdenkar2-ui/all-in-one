# Backend contract

## Requested outcome and authority
Record the user's outcome, authorized delivery destination, binding decisions, and exact source/version.

## Existing system
Record runtime/library versions, boundaries, consumers, data ownership, existing tests, and user changes.

## Inputs, outputs, and invariants
Define API/event schemas, state transitions, identifiers, compatibility, and constraints.

## Failure and security behavior
Define acknowledgement, timeout, cancellation, duplicate/retry handling, recovery, tenant authorization, and secret handling.

## Acceptance evidence
For each requirement name its observable outcome and relevant test. Record resource targets and representative workload only when required.

## Decisions and limits
Distinguish settled choices, implementation assumptions, unavailable checks, and material unanswered requirements.
