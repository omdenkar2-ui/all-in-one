# Backend skill catalog

Invoke a stage by its full plugin name, for example `$all-in-one:aio-plan`. All in One routes requests; Complete Destruction owns autonomous execution. Specialists use the [shared stage contract](stage-contracts.md) and return to their caller. Consult only relevant [work modes](modes.md), separately from resource profiles.

| Stage | Phase | Responsibility |
| --- | --- | --- |
| [aio-compound](../../aio-compound/SKILL.md) | continuity | Capture a verified backend investigation as a searchable original lesson when its causal reasoning is absent from code, tests and existing docs; update stale lessons instead of creating duplicates. Use after non-obvious agent, pipeline, data or recovery work is solved. |
| [aio-handoff](../../aio-handoff/SKILL.md) | continuity | Save a concise, source-anchored backend execution handoff that another session can safely resume. |
| [aio-resume](../../aio-resume/SKILL.md) | continuity | Resume the exact saved backend run after reconciling its ledger with current source and evidence. |
| [aio-worktree](../../aio-worktree/SKILL.md) | continuity | Set up isolated backend work ownership without discarding or silently copying unrelated changes. |
| [aio-ci](../../aio-ci/SKILL.md) | delivery | Follow required backend PR or build checks to an observed terminal result without inventing CI success. |
| [aio-commit](../../aio-commit/SKILL.md) | delivery | Create a focused local commit after inspecting owned backend changes and validation evidence. |
| [aio-feedback](../../aio-feedback/SKILL.md) | delivery | Resolve backend PR review feedback with evidence, scoped repairs and renewed checks. |
| [aio-release](../../aio-release/SKILL.md) | delivery | Prepare and verify backend rollout, compatibility, canary signals and recovery before authorized deployment. |
| [aio-ship](../../aio-ship/SKILL.md) | delivery | Deliver a verified backend change locally, through a requested PR, or to an authorized deployment target. Use for shipping after implementation/review or refreshing a PR description; follows exact-head CI and reports pending or blocked states truthfully. |
| [aio-brainstorm](../../aio-brainstorm/SKILL.md) | discovery | Explore ambiguous backend, API, agent or workflow ideas into a bounded requirements brief with alternatives and observable success. Use before architecture or planning when the outcome or scope is unsettled. |
| [aio-ideate](../../aio-ideate/SKILL.md) | discovery | Generate and rank backend or agent-system approaches before committing to a design. |
| [aio-prototype](../../aio-prototype/SKILL.md) | discovery | Run a bounded backend architecture spike to resolve a specific technical uncertainty. |
| [aio-spec](../../aio-spec/SKILL.md) | discovery | Turn accepted backend behavior into versioned requirements, interfaces and acceptance criteria. |
| [aio-agents](../../aio-agents/SKILL.md) | implementation | Engineer agent state, tool authority, model decisions, budgets and durable checkpoint recovery. |
| [aio-algorithms](../../aio-algorithms/SKILL.md) | implementation | Build and verify backend algorithms with independent oracles and explicit resource bounds. |
| [aio-api](../../aio-api/SKILL.md) | implementation | Build or evolve backend API, webhook and event contracts with security and compatibility checks. |
| [aio-data](../../aio-data/SKILL.md) | implementation | Plan and implement backend schemas, transactions, tenant access and compatible data migrations. |
| [aio-debug](../../aio-debug/SKILL.md) | implementation | Diagnose a backend bug, failed test, CI failure, agent/tool issue or pipeline incident by reproducing it, tracing boundaries and testing a causal hypothesis before a targeted fix. Use when behavior is unexplained or previous patches have not resolved it. |
| [aio-pipelines](../../aio-pipelines/SKILL.md) | implementation | Engineer queue jobs, durable workflows, DAGs and backfills with explicit recovery semantics. |
| [aio-tdd](../../aio-tdd/SKILL.md) | implementation | Implement changed backend behavior through observed failing tests, minimal fixes and refactoring. |
| [aio-work](../../aio-work/SKILL.md) | implementation | Implement an accepted backend plan or concrete build request through test-first units, ordered spec and risk reviews, and integrated verification. Use for backend execution or resuming an exact implementation run; use aio-debug for unexplained failures. |
| [aio-explain](../../aio-explain/SKILL.md) | inspection | Explain a backend or agent workflow from actual code, state, data and failure boundaries. |
| [aio-canary](../../aio-canary/SKILL.md) | operations | Observe a bounded backend canary or post-deploy window against identified baselines, configured thresholds and real functional effects. Use for baseline capture or deployment health checks; rollout and rollback require existing authorization. |
| [aio-observe](../../aio-observe/SKILL.md) | operations | Establish backend and agent telemetry, operational checks and actionable recovery signals. |
| [aio-optimize](../../aio-optimize/SKILL.md) | optimization | Diagnose and improve backend performance using representative profiles and correctness checks. |
| [aio-architecture](../../aio-architecture/SKILL.md) | planning | Design backend and AI agent execution architecture with typed state, authority boundaries, durable recovery, interfaces and resource budgets. Use for consequential architecture choices or workflow design before implementation. |
| [aio-autoplan](../../aio-autoplan/SKILL.md) | planning | Automatically refine and independently review an executable backend plan, with scope and developer-interface checks before engineering review. Use for autoplan or automatic backend planning; return to an authorized build controller without starting another pipeline. |
| [aio-plan](../../aio-plan/SKILL.md) | planning | Create an execution-ready backend implementation plan with stable requirements, owned units, exact interfaces, test-first verification and a dependency graph. Use for multi-step backend, agent, pipeline or algorithm work before changing production code. |
| [aio-plan-review](../../aio-plan-review/SKILL.md) | planning | Check a backend implementation plan for requirement coverage, feasibility and adversarial failures. |
| [aio-devex-review](../../aio-devex-review/SKILL.md) | review | Review the actual backend API, SDK or CLI developer journey, examples, errors and compatibility. Use to measure integration friction and diagnose developer-facing contract gaps; report-only unless fixes are authorized. |
| [aio-doc-review](../../aio-doc-review/SKILL.md) | review | Review backend plans, API contracts and runbooks for contradictions, gaps and stale operational claims. |
| [aio-review](../../aio-review/SKILL.md) | review | Review a named backend diff or PR against its contract, then inspect correctness, security, test quality and failure recovery. Use for unit, fix-range or whole-change review with evidence-backed findings; report-only unless applying fixes is requested. |
| [aio-security](../../aio-security/SKILL.md) | review | Audit backend trust boundaries, agent tools, tenant access and data exposure. Default to static inspection; use controlled reproduction and authorized hardening when requested. |
| [aio-simplify](../../aio-simplify/SKILL.md) | review | Simplify backend changes without weakening contracts, failure behavior or test coverage. |
| [aio-test-audit](../../aio-test-audit/SKILL.md) | review | Audit the value of existing backend tests with a bounded shortlist, actual callers and regression evidence. Use for test-suite cleanup or confidence gaps; report-only unless test changes are authorized. |
| [aio-benchmark](../../aio-benchmark/SKILL.md) | verification | Run a fair, predeclared backend comparison of two or three workflows chosen from All in One, Compound Engineering and Superpowers using the same task, model settings and evaluator. Use when evidence is needed for a scoped quality or performance claim. |
| [aio-checkpoint](../../aio-checkpoint/SKILL.md) | verification | Reconcile backend plan, units, review and verification evidence before advancing a pipeline stage. |
| [aio-proof](../../aio-proof/SKILL.md) | verification | Collect reproducible backend acceptance evidence bound to source and candidate artifacts. |
| [aio-qa](../../aio-qa/SKILL.md) | verification | Explore backend API, CLI, job, worker and webhook behavior, then repair authorized reproducible defects and verify durable outcomes. Use for backend QA, quick QA or replaying a prior regression report; use aio-qa-only for report-only inspection. |
| [aio-qa-only](../../aio-qa-only/SKILL.md) | verification | Report-only backend functional QA using Full, Quick or Regression exploration. Reproduce defects and retain evidence without repairing code, changing dependencies or shipping. Use for qa-only, an inspection-only QA report or verifying a previous failure report. |
| [aio-test](../../aio-test/SKILL.md) | verification | Design and run backend boundary tests, fault injection and independent correctness oracles. |
| [aio-verify](../../aio-verify/SKILL.md) | verification | Verify backend acceptance and completion against fresh tests, source snapshots and delivery evidence. Use before closing or shipping backend work, checking completion claims, or reporting configured local health checks. |

The seven older backend names delegate to canonical AIO stages. Launch readiness and its two copied store specialists apply only when mobile release is requested.

REA is the optional artifact-analysis specialist: [reverse-engineer-anything](../../reverse-engineer-anything/SKILL.md). It runs only when the requested evidence requires a shipped artifact or runtime investigation; return findings to the current controller. See [REA integration](rea-integration.md) for connection details.

See [upstream design](upstream-design.md) for source adaptations and comparison limits.
