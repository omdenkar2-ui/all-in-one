# Backend outcome brief

## Goal and authority

State the caller/operator outcome, accepted scope, delivery destination and existing implementation authorization. Name the exact request or source and its provenance.

## Current evidence

Record the inspected repository paths, interfaces, current stack and relevant behavior. Separate observations from hypotheses. Include only facts that affect decisions.

## Requirements

For each stable `R1` requirement, record the behavior, affected actor, observable acceptance and owning constraint. Give numerical values only when supplied or supported; otherwise state the unresolved target and how to establish it.

## Alternatives and decisions

Compare viable approaches against the same requirements. Record each consequential decision as `D1`: choice, rejected alternative, evidence, tradeoff, decision source and reversibility.

## Scope and unresolved facts

Record explicit exclusions, dependencies and genuine blockers. State the decision or evidence needed to remove each blocker.

## Handoff

State `ready_for_planning` or `blocked`, the canonical source path and which requirements still need resolution. A planning-ready brief is not a tested implementation.
