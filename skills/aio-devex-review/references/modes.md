# Backend developer journey modes

Use the explicitly requested mode; otherwise retain **DX POLISH**. Pin the developer, API/SDK/CLI surface, supported version, starting conditions and representative journey before applying the lens. A mode is not authority to add endpoints, languages, platforms or external actions.

| Mode | Focus |
| --- | --- |
| **DX EXPANSION** | Exercise the accepted representative path and recovery case, then propose backend integration improvements beyond it when evidence shows concrete value. State the developer benefit, compatibility impact, effort and operational cost. Keep proposals separate until accepted. |
| **DX POLISH**, default | Inspect setup through successful use and a representative recovery path within the accepted journey. Improve precision of examples, defaults, help, errors and relevant compatibility observations without redesigning established contracts to improve a score. |
| **DX TRIAGE** | Focus on material blockers from prerequisites/install/auth/configuration through the first successful API request, SDK operation or CLI command. Follow a bounded recovery path where it explains a blocker. Prioritize unusable instructions, missing required configuration, misleading success and failures with no actionable remedy. |

Triage narrows optional review coverage; it cannot waive an explicitly requested compatibility check or accepted verification. Label later usage, debugging and upgrade dimensions unassessed when omitted. A working hello-world path does not establish full DX coverage, adoption, security or release readiness. Polish and expansion also retain the representative path limit rather than sampling every surface.

Keep observations measured, inferred or blocked as defined by the entrypoint. Missing optional dimensions remain unassessed, never zero scores or passes. Return the selected mode, actual coverage, material findings and remaining gaps. Use the same controller journal, dispatch/repair caps and remaining deadline; do not create a reviewer for every dimension. Fix only within existing authorization, then rerun the affected journey under the controller's budget.
